# Remotion 科普视频全流程（中文版）

> 英文版为 [SKILL.md](SKILL.md)，两者内容一致。Claude 实际加载的是 `SKILL.md`；本文件供中文读者阅读。

用 Remotion 做抖音风格的科普/教学动画视频的可复用流程：选题 → 带拍点的分镜 → 音乐卡点 → 音效与音量平衡 → 渲染 → 审片 → 封面（3:4、4:3）→ 发布文案 → 数据复盘。

按顺序执行，每个确认点都要停下来等用户确认，不要跳步。文中路径都相对于项目根目录（即含 `package.json` 的文件夹），`<project>` 请替换为实际路径。

## 0. 默认规格（用户另有要求才改）

- 默认横屏 1920×1080、60fps。仅当用户要求时才用 30fps。
- 无配音，中文字幕烧录在画面上，字幕放在底部约 350px 以上（避开平台界面遮挡）。
- 目标时长 45–75 秒。内容较多时拆成系列。开头足够强时，100–120 秒也可以接受。
- 背景音乐：由用户提供，放在 `public/` 中，并记录来源。如果用户没有可用的音乐，可以用脚本生成节拍氛围音乐。

## 1. 选题（等用户选定）

- 给出 3–5 个候选。每个都要说明：
  - 一句话钩子（首帧的大字问题）；
  - 观众看完能复述的“原来如此”机制；
  - 一个日常生活中的例子；
  - 为什么能留住观众。
- 避开已经被做烂的题目，以及只有事实罗列、没有推理链条的题目。
- 检验标准：看完后，观众能否用一句话讲给朋友听？

## 2. 分镜（等用户通过）

在视频文件夹中写 `分镜.md`，必须包含：

1. **音乐分析**：BPM、小节数、段落（如 drop、过门、低通段），以及每段结束的秒数和小节号。
2. **逐镜表**：时间（秒）加上小节.拍（如 `V06.1`）、画面、运镜、字幕和大字、音效，以及每个切镜落在哪一拍。
3. **开头 0–2 秒设计**：第一帧就要有画面和问题。观众先猜一个答案（通常是错的），随后视频反转。
4. **科学依据和案例出处**。
5. **2–3 张样帧**，让用户在开工前判断画面风格。

所有时间统一写成“小节.拍”。画面、字幕、音效共用同一份节拍数据，改时间只需改小节号。

用户说“开始制作”就动手；说“修改”就改分镜，再次等待确认。

## 3. 音乐卡点

- 用 librosa（在本地 `.venv` 中）分析音轨，得到 BPM 和强拍，把每个切镜和关键动作对到拍上。
- 如果用户想要不同的时长或节奏，用“按小节截取、拼接”的方式重排（不要拉伸，以免变调）。
- 高潮（drop）放在揭晓答案或主角登场处。过门用来留白，一拍一个元素。
- 节奏偏慢时，把读字镜头拉成两个小节，每两拍一个动作；过门镜头多停留一小节。

## 4. 音效与混音（用户最常提的反馈）

- **风格**：柔和、干净、音色化，接近纪念碑谷、信息可视化的感觉：马林巴、钟、玻璃、柔和的 whoosh、低频脉冲。
- **避免**：写实的刹车尖叫、喇叭、刺耳的重复音效。表现“刹车”或“放大”时，用音高逐步下降、一次比一次厚重的音色代替。
- **音量**（以下数值在两个项目中验证过）：
  - 音乐增益约 ×0.6；
  - 音效峰值约 −5.5 至 −7 dBFS，中位数比音乐低约 5–9 dB；
  - 成片响度约 −17 dBFS RMS，并用软限幅防止爆音。
  - 交付前按场景做测量（`ffmpeg -af volumedetect` 或 numpy 计算 RMS）。
- **层次**：音效放在空隙或拍点上，不要压在主旋律上。
- **结尾**：画面和音乐在最后 2–2.5 秒一起淡出，不要突然切断。
- **开头**：可以加 1 秒无音乐的引入段，用于“问题渐入、场景加载”。

## 5. 开工与渲染

- 推荐的项目结构：
  - `src/data/`：节拍、时间线、镜头 JSON；
  - `src/*.tsx`：各个场景；
  - `scripts/`：音乐、音频、静帧、接触图脚本；
  - `package.json`：包含 `music`、`audio`、`render`（`remotion render Main out/video.mp4`）、`typecheck` 等脚本。
- 新项目如果从已有项目复制，macOS 上用写时复制（`cp -Rc`）复制 `node_modules`，Python 虚拟环境用软链接，不要重装。
- 渲染使用 `npm run render`。渲染可能需要在沙箱外运行。
- 渲染后检查：分辨率、帧率、时长、音轨是否存在、各场景音量，以及帧接触图。如果无法听音频，要告诉用户“只做了数值测量，请亲自听一遍”。

## 6. 用户审片

- 把成片发给用户。
- 逐条修改。常见反馈：音效与音乐的平衡、节奏、结尾、字幕位置、画面不清楚的地方。
- 用户确认“没问题”之后再做封面。

## 7. 封面（3:4 和 4:3 各一张）

- 3:4 = 1080×1440，用于信息流主推；4:3 = 1440×1080，用于合集和主页。
- 大字钩子使用与首帧相同的问题，关键词用强调色。缩略图尺寸下要清晰可读。
- 可以从视频首帧截取，也可以设计静态图。交付前自己先看一遍。

## 8. 发布文案（`发布文案.md`）

- 3–5 个标题，每个写明理由，推荐其中一个。标题里要有能被搜索到的词（如话题的日常说法 + “为什么”），不要只用项目名。
- 2–4 句简介，结尾引导评论。
- 话题标签：1 个主话题 + 2–3 个人群话题 + 1–2 个内容话题，总共 5–8 个。
- 热点方向只作为建议列出。要说明没有核实实时热榜，请用户自己在平台上确认。
- 置顶评论：用投票或提问引导讨论。
- 发布小贴士：前两秒就是问题；横屏视频在信息流中显示较小，所以优先用 3:4 封面。

## 9. 发布与复盘

- 由用户自己发布，不代替用户发布。
- 发布一两天后，请用户提供数据：2 秒跳出率、5 秒完播率、平均观看时长、完播率、点赞率、推荐与搜索占比。样本小时结论只作参考，不要编造数字。
- 把结论转化为下一条视频的具体改法，并记录在项目笔记中。

## 常见坑

- 音乐比音效大：先压低音乐，再把音效提到目标电平。
- 结尾硬切：加淡出。
- 刺耳的写实音效：换成音色化的声音。
- 节奏太快看不完：拉长读字镜头。
- 元素被遮挡（如印章压住图表）：通过接触图检查。
- 非 ASCII 文件名的 shell 引号问题：使用绝对路径并加引号。
- 登录：不要替用户登录任何网站或平台。
